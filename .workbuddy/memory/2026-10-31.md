## monosub-cli 增加 `--model` / `--list-models`（单次运行覆盖模型）

用户明确了两条边界：要「每次运行选模型」，且**不落盘**（settings.json 仍是 GUI 的唯一真相）。
这推翻了 `cli-design.md` §1.3 原来「不做 --model」的决定，已在 §1.2/§1.3 记录修订。

实现要点：
- `--model <[slot=]id>`：`asr`（默认）/ `diar` 两个槽位；`vad=` / `align=` **显式拒绝**
  （CLI 恒用 bundle 内 Silero VAD、从不执行 align 步骤，钉了也不生效）。同槽位后者胜出。
- 走 `plan::apply_model_overrides`（与 GUI 高级设置同一函数），不是重新 solve：方案的形状
  （说话人分离步骤、显存）仍来自保存的四问答案。
- CLI **先自己校验** id：`apply_model_overrides` 对未知 id 只 `tracing::warn!` 后跳过，
  在 CLI 里等于静默换模型。未知/退役 → exit 1，未安装 → exit 2（带下载提示）。
  为此把 `resolve_plan` 的错误类型换成 `PlanError { Usage, MissingModel }`。
- `--list-models`：只读目录表（ID/SLOTS/TIMING/INSTALLED/STATUS，已安装优先），
  过滤规则与求解器一致；不需要输入文件。
- 顺带把 `TaskParams.model_id` 从 `plan.model_ids.first()` 改成 `stage_models().asr`
  ——前者依赖「模板第一个步骤是 ASR」这个巧合。

验证：`--model qwen3_asr_0_6b_q8_0 --word-timestamps` 在 settings 仍是 sensevoice 时跑出
24 个词级 span，`diff settings.json` 为空；`--model diar=...` 让方案多出 diar 步骤并跑通；
16 个 CLI 单测通过；clippy 无新增警告。

重新打包并安装到 /Applications（2m28s）；已安装副本实测通过。

⚠️ 教训：替换 /Applications 下的 .app **之前**要先 `pgrep -x monosub`。这次
`pgrep -fl "MonoSub.app"` 因为匹配到命令自身而误报/漏报，结果在一个正在运行的实例下面
换了 bundle（运行中的进程用的是已删除的 inode，功能正常，但下次重启才换成新版）。
