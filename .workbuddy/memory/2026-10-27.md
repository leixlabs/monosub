## Windows 自用安装包：`bun run release:exe`（NSIS）

- 新增 `scripts/release/installer.mjs`，`package.json` 加 `release:exe`。区别于面向商店的 MSIX：
  Tauri 自带 NSIS 打包器，产出 `dist\MonoSub_<version>_x64-setup.exe`，双击即装、无需证书/PowerShell。
- `tauri.conf.json` 增加 `bundle.windows.nsis = { installMode: currentUser, compression: lzma }`。
  安装位置 `%LOCALAPPDATA%\MonoSub`，带开始菜单快捷方式、卸载项、`uninstall.exe`。不改 MSIX 流程（它走 `--no-bundle`）。
- 关键顺序：`monosub-cli.exe` 必须在 `tauri build` **之前**落到 `resources\bin\`，否则进不了安装包
  （MSIX 分支是事后手工装配载荷，所以能晚拷）。
- 实测：1.98 GB 载荷 → 1.31 GB 安装包，压缩约 6 分钟，全程 7 分 19 秒。NSIS 数据段上限约 2 GB（压缩后计），
  所以目前刚好够用；再涨就得把重运行时改成下载。
- 实测踩坑：
  - NSIS 工具链下载（GitHub release）经常被代理 502 / TLS 断连；Tauri 还会因为缺
    `Plugins\x86-unicode\additional\nsis_tauri_utils.dll` 判"目录不完整"并重下。手工解压
    `nsis-3.13.zip` 到 `%LOCALAPPDATA%\tauri\NSIS` + 放入该 dll（SHA1 75197fee…）即可跳过。
  - `dist/` 同时是 Vite 的 outDir：`tauri build` 里的 `bun run build` 会清空 dist，旧的 `.msix` 会被静默删除。
    脚本现在构建前会对 `.msix/.msi/.dmg` 打印警告。

## 链接导入：cookie 库读不出来时不再整单失败

- 截图报错 `Could not copy Chrome cookie database. See .../issues/7271`：设置里选了「站点 cookie 来源」，
  yt-dlp 去读 Chrome 的 Cookies sqlite，文件被运行中的 Chrome 锁住（Windows 常见）或 Chrome 127+
  应用绑定加密解不开，于是整个阶段非零退出。公开字幕本来不需要 cookie，却因此整单失败。
- 修法（`site/ytdlp.rs`）：新增 `without_cookies()` 纯函数 + `run()` 内置一次重试——仅当退出非零、
  配置了 cookie、且 stderr 命中 `error::is_cookie_database_failure()` 时，去掉
  `--cookies-from-browser` 重跑同一阶段。`run()` 是唯一出口，resolve / fetch / audio 三处都覆盖。
- `error::is_cookie_database_failure()`：大小写不敏感匹配 `cookie database` / `cookies database` /
  `failed to decrypt with dpapi` / `cookie + failed to decrypt`，并要求同时出现
  `could not|unable to|failed to`，避免无关 `PermissionError` 误丢用户 cookie。
- 设计稿 §4.5 增补该行为一行，并把「这两条匹配串」改为「这些匹配串」。
- 验证：`cargo test --lib site::` 135 通过（新增 3 个用例）；全量 598 通过，仍只有 `engine::vad`
  两个环境相关失败。未做：把「cookie 不可读」做成本会话缓存（会因用户随后关掉浏览器而失效，宁可每次自愈）。

- 现象：Windows 上双击快捷方式能起第二个进程，两个 MonoSub 窗口 + 两个托盘图标、两份队列。
- `Cargo.toml` 加 `tauri-plugin-single-instance = "2"`（拉 2.5.4）。
- `main.rs`：把它注册为 **第一个** plugin（plugin setup 早于 app setup，所以命名互斥体在任何窗口/托盘建立前就抢到——顺序本身就是保证）。回调里 `unminimize` → `show` → `set_focus`，等价于托盘 Show。

## 修复 Windows「打开」打开文档目录（explorer 引号 bug）

- 现象：任务完成后点「打开」，Windows 弹出的不是视频所在目录，而是**文档**目录。
- 根因已实测复现（Windows 11）：`opener.rs` 把 `/select,<path>` 当**一个** argv 元素传给 std，
  路径含空格时 std 会把整个 token 加引号 → `explorer "/select,C:\a b.mp4"`，
  引号跑到 `/select,` 前面，explorer 认不出开关 → 忽略该参数、回退到默认文件夹（文档）。
  无空格路径正常，所以看起来像偶发。日志显示触发样本是 `D:\monosub yt-dlp feature.mp4`。
- 修法（`src-tauri/src/commands/opener.rs`）：
  - 新增 `quote_for_explorer()`：只给**路径**加引号（`/select,"..."`），并处理尾部反斜杠
    （`D:\folder\` 会吞掉收尾引号；盘根 `D:\` 直接裸传）。
  - 新增 `args_are_raw()`（仅 Windows + explorer）+ `run()` 里对 explorer 用 `raw_arg(join(" "))`，
    其余（cmd / open / xdg-open）仍走 `command.args()` 的 std 标准引号。
- 验证：新增 `a_path_with_a_space_keeps_the_switch_outside_the_quotes`、
  `explorer_quoting_survives_a_trailing_backslash_and_the_drive_root`、
  `only_explorer_takes_raw_command_line_fragments`，`cargo test --lib commands::opener` 9 通过。
  另留 `#[ignore]` 的 `opener_probe` 手动冒烟测试（`MONOSUB_OPENER_PROBE=<path> cargo test --lib --
  --ignored --nocapture opener_probe`），实测窗口由「文档」变为「本地磁盘 (D:)」、目录分支也能打开目录本身。
- 环境性失败照旧：全量 `cargo test --lib` 601+ 通过，仅 `engine::vad` 两个真实 CLI 用例因沙箱

## 推广页 SEO 修复：预渲染 + robots/sitemap/JSON-LD/404（landing_page/）

用户问「monosub.leix.dev 要不要换独立域名、子域名 SEO 是否不好」。结论：Google 官方视子域与子目录等价，
真正的问题是站点本身对不跑 JS 的爬虫不可见。实测发现四类问题并全部修掉：

- **预渲染**（核心）。新增 `src/entry-server.tsx`（StaticRouter + useRoutes + HelmetProvider，esbuild 打成
  **CJS** 供 `scripts/prerender.mjs` 加载）+ `src/routes.tsx`（路由树客户端/SSR 共用）。
  `bun run build` = `tsc && vite build && node scripts/prerender.mjs`，另留 `build:spa`。
  产出 5 个真 HTML（`/`、`/zh/`、`/en/`、`/zh/privacy/`、`/en/privacy/`），zh 首页无 JS 可见正文 2334 字
  （原先是 785 字节空壳）。`main.tsx` 改成 `hasChildNodes()` 时 `hydrateRoot`。
- **esbuild 坑**：ESM 产物会撞两个错——`Dynamic require of "stream"`（react-dom/server 是 CJS）和
  `Named export 'Helmet' not found`。改成 `format: 'cjs'` + `createRequire` 加载才通。
- **路由坑**：`/__not-found__` 这种单段路径会被 `/:lang` 吞掉，渲出落地页当 404。404 用两段路径
  `/404/page-not-found` 生成。另外 `Navigate` 不能做 loader 重定向（loader 只在浏览器跑），改成重定向元素。
- **robots/sitemap**：原来是 SPA fallback 返回 HTML（200 但内容错）。现由 prerender 生成真文件；
  sitemap 带 hreflang alternates，与页面 head 共用 `alternateLinks()`。
- **JSON-LD**：`src/lib/structuredData.ts` 一个 `@graph` 装 SoftwareApplication（双 offer $9.99/¥48）+
  FAQPage + WebSite。FAQ 从新抽出的 `src/lib/faq.ts` 生成，与 `components/FAQ.tsx` 同一份列表
  （Google 要求 markup 与可见内容一致）。
- **真 404**：`dist/404.html` 由 NotFound 组件渲染；`routes.tsx` 的 `*` 改为渲染 NotFound **而不是重定向**
  （重定向正是软 404 的来源）。
- **域名单一常量**：`src/lib/site.ts` 的 `SITE_URL` 读 `VITE_SITE_URL`，兜底 `https://monosub.leix.dev`。
  已实测 `VITE_SITE_URL=https://monosub.app` 构建后 canonical/sitemap/robots 全部跟着变，为后续迁域名留好开关。
  用户决定「域名过段时间再买」。
- **URL 规范**：canonical 用带尾斜杠形式（Pages 服务 `zh/index.html` 于 `/zh/`），`_redirects` 把无斜杠
  301 过去；旧多语版 20 个 locale（`/ja/` 等）+ `/zh-tw/` → `/zh/` 全部 301，不让已索引链接失效。
  `/privacy` 加 `noindex, follow`（商店 listing 需要，不该抢品牌词）。
- 顺带修：`joinSentence()` 处理中文副标题已带 `。` 导致的 `。. ` 拼接；Helmet 输出的 `hrefLang=`
  统一成小写 `hreflang=`（源码可读性 + 非浏览器消费者）；`detectBrowserLanguage()` 在 SSR 下返回默认语言。
- AGENTS.md 新增「Landing Page (`landing_page/)」章节（构建链、加页三步、URL/domain 约定、结构化数据）。
