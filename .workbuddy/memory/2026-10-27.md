## Windows 自用安装包：`bun run release:exe`（NSIS）

- 新增 `scripts/release/installer.mjs`，`package.json` 加 `release:exe`。区别于面向商店的 MSIX：
  Tauri 自带 NSIS 打包器，产出 `dist\MonoSub_<version>_x64-setup.exe`，双击即装、无需证书/PowerShell。
- `tauri.conf.json` 增加 `bundle.windows.nsis = { installMode: currentUser, compression: lzma }`。
  安装位置 `%LOCALAPPDATA%\MonoSub`，带开始菜单快捷方式、卸载项、`uninstall.exe`。不改 MSIX 流程（它走 `--no-bundle`）。
- 关键顺序：`monosub-cli.exe` 必须在 `tauri build` **之前**落到 `resources\bin\`，否则进不了安装包
  （MSIX 分支是事后手工装配载荷，所以能晚拷）。
- 实测：1.98 GB 载荷 → 1.31 GB 安装包，压缩约 6 分钟，全程 7 分 19 秒。NSIS 数据段上限约 2 GB（压缩后计），
  所以目前刚好够用；再涨就得把重运行时改成下载。
- 实测踩坑：
  - NSIS 工具链下载（GitHub release）经常被代理 502 / TLS 断连；Tauri 还会因为缺
    `Plugins\x86-unicode\additional\nsis_tauri_utils.dll` 判"目录不完整"并重下。手工解压
    `nsis-3.13.zip` 到 `%LOCALAPPDATA%\tauri\NSIS` + 放入该 dll（SHA1 75197fee…）即可跳过。
  - `dist/` 同时是 Vite 的 outDir：`tauri build` 里的 `bun run build` 会清空 dist，旧的 `.msix` 会被静默删除。
    脚本现在构建前会对 `.msix/.msi/.dmg` 打印警告。
- 文档：AGENTS.md 增加 "Windows self-install: NSIS .exe" 小节（三种产物的对照表 + 上述限制）。

## 链接导入：新增 YouTube 支持 + 修复 yt-dlp 非 UTF-8 读取崩溃

- `site/url.rs`：新增 `YOUTUBE_HOSTS`（youtube.com / www / m / music / youtube-nocookie / youtu.be），
  只接受单视频形态（`watch?v=`、`/shorts/`、`/live/`、`/embed/`、`/v/`、短链），统一规范到
  `www.youtube.com`；短链重写为 `/watch?v=<id>`；丢弃 `si/pp/feature/ab_channel` 分享参数以便去重，
  保留 `list`/`t`。非视频页返回 `unsupported_kind`。
- `site/clipboard.rs`：一键导入提示复用同一解析器；`video_id` 改为优先取 YouTube 的 `v` 参数，
  非 URL 的裸 ID 回退到旧逻辑。
- `site/resolve.rs`：`SiteMedia` 新增 `auto_subs`（`automatic_captions`）与 `raw_info`
  （yt-dlp 原始 info dict 文本，抓取阶段优先原样写盘，避免裁剪后丢 `webpage_url`）。
  `SubTrack.raw` 保留原始格式条目（含 URL）。
- `site/lang.rs`：`Pick.automatic` 区分轨道来源；自动轨只接受 `<lang>-orig`，避免把 YouTube
  机翻轨当原语字幕（`accepts_auto` 不做 `ai-` 前缀判定）。
- `site/ytdlp.rs`：`FetchSubtitles` 带 `automatic`，据此选 `--write-auto-subs` / `--write-subs`；
  字幕阶段统一 `--convert-subs srt`（VTT → SRT，依赖随包 ffmpeg）。
- **修复截图 bug**：`failed to read yt-dlp stdout: stream did not contain valid UTF-8`。
  Windows 下 frozen yt-dlp 可能按控制台代码页输出非 UTF-8 字节，`BufReader::lines()` 会整条流失败。
  改为 `read_line_lossy`：先按 `\n` 切字节再 `from_utf8_lossy`，并给子进程设
  `PYTHONIOENCODING=utf-8` / `PYTHONUTF8=1`。
- 文案去品牌：i18n `urlImport.hint` 改为「支持的视频链接」，设计稿 ASCII 示意图与 AGENTS.md
  功能条目去掉站点名称（用户要求避免侵权）。
- 验证：`cargo test --lib site::` 132 通过；`bun run check`、`bun run check:i18n` 通过。
  全量 `cargo test --lib` 仅 `engine::vad` 两个真实 CLI 用例因本机 PermissionDenied 失败（环境问题）。
- 未做（需另立项）：打包 JS 运行时（Deno 等，YouTube 完整提取需要）、`--proxy` 设置项、
  YouTube 专属错误分类（年龄/地区限制）。

## 链接导入：字幕语言改为跟随界面语言

- 问题：导入面板的 Subtitle language 映射的是 `settings.outputLanguage`（设置里叫「识别语言」），
  该值按 `navigator.language` 首次初始化并持久化，所以界面切到英文后仍显示 Chinese。
- 规则：字幕是给人读的 → 取界面语言；`outputLanguage` 描述音频，仅用于本地识别，两者解耦。
- `src/lib/urlImport.ts` 新增 `subtitleLanguageForUi(lang)` / `uiSubtitleLanguage()`，`start_url_import`
  的 `language` 改用它（不再发送 `auto`，因此导入总会先尝试平台字幕）。
- `UrlImportDialog` 用同一映射渲染，并新增 `urlImport.followsInterfaceLanguage` 文案（中英同步）。
- 设计稿 §5.2 的说明同步更新；`bun run check` / `check:i18n` / `cargo test --lib site::` 均通过。
