## 沙盒下"输出到同目录"改为：先授权说明，再系统面板

问题：MAS/沙盒构建下用户选完文件还要再选一次目录（第一次转写必然 EPERM）。

调研结论（已核实）：
- 从"选文件"推不出父目录写权限，对父目录建 security-scoped bookmark 也无效
  （能建能解，`startAccessingSecurityScopedResource()` 返回 false）。
- Apple 的 Related Items（`NSIsRelatedItemType` + NSFilePresenter/NSFileCoordinator）
  官方 WWDC 2019 701 就是用"视频 + 字幕"举例，理论上可行；但有硬伤：只覆盖
  "同名换扩展名"，`<stem>.<lang>.<ext>`（翻译产物）不在范围；要声明 srt/vtt/txt/md/json
  多种文档类型（role 必须 Editor）；且 Apple DTS 自己称其 "quite obscure"。
  → 暂不采用，留作后续 spike。

实现（按用户要求保留"同目录"）：
- Rust：新增 `output_dir_writable(path)`（探写）、`app_sandboxed()`；`paths::dir_accepts_writes`
  改 pub。注册在 main.rs。
- `src/lib/grants.ts`：`bootstrapSandboxFlag()`（结果写 store.isSandboxed）、
  `ensureOutputAccess(源目录列表)`、`parentDir()`、以及一个 Promise 化的对话框请求
  （`askFolderGrant/getFolderGrantRequest/answerFolderGrant`）。
- `src/components/FolderGrantDialog.tsx`：应用内说明层，点"授权"后才弹系统目录面板，
  `defaultPath` 指到源目录；面板确认后 `authorize_dir` 存 bookmark。
- 接入点：`Toolbar.handleStartAll`（整批源目录一次收齐）、`transcription.startTranscriptionTask`
  （兜住单文件/URL 自动开始）。用户取消 → 不派发，行内 `errors.outputFolderRequired`。
- 面板里选了别的目录 → 视为"放这里"，切 custom 模式，后续不再逐个问。
- `store.isSandboxed` 运行时字段，不进 partialize。

文档：`docs/release/mas-app-store.md` §3.1 表格重写；AGENTS.md 状态字段补充。

验证：tsc / i18n 键一致性 / eslint(0 error) / vite build / cargo check 全过。未做真机沙盒验证。

## 设置 · 模型列表：点下载后不再重排

原因：`sortByAvailability(models, downloadingId)` 在渲染期重算，把"已装 / 下载中 / 未装"
三段分开，所以点 Download 那一刻行会跳到"下载中"段首，下载完成又跳进"已装"段。

修法（快照式排序，不是在渲染期算）：
- `lib/models.ts::sortByAvailability(models)` 去掉 `downloadingId` 与"下载中置顶"分支，
  只在加载目录时调用一次。
- `Settings.loadModels()` 里 `setModels(sortByAvailability(list))`——列表顺序成为加载时刻的快照；
  之后的 `setModels(map)`（下载完成 / 删除）只改字段、不动位置。
- `Settings.tsx` 的 `recognition` / `translation`、`SettingsTranslation` 的 `available` 改成纯过滤，
  不再排序，所以两个面板共用同一顺序、都不会漂移。
- 重新打开设置或点刷新 = 重新取目录 = 重新应用"已装优先"。
- 验证：tsc / eslint(0 error) / vite build 通过。

## 模型下载支持断点续传（P4-4）

结论：没有合适的现成 crate（`reqwest-download` 在 crates.io 上不存在；`hf-hub` 是 HF API 专用、
不暴露通用 URL 续传；`downloader-rs` 下载量太小且自管临时文件命名，会和 `.part` 契约 /
`cancel_model_download` / sha256 校验 / 镜像回退打架）。所以续传仍建在已有的 reqwest 上——
续传本来就是"Range 头 + 追加写"，不算从零实现 HTTP。

`commands/models.rs`：
- `transfer()` 签名加 `expected_size`，返回 `u64`（起始偏移）。有 `.part` 时带
  `Range: bytes=<len>-`；`206` 用 `content_range_start()` 校验起点与总长均与清单一致才追加，
  `200`（服务器忽略 Range）截断重写，`416` / 206 不合法则删 `.part` 后重试一次（只允许一次）。
- `.part` 长度 > 清单 size → 视为别的版本，丢弃；== size（flush 后 rename 前崩溃）→ 不发请求直接交给校验。
- 取消 / 网络失败不再删 `.part`（它就是续传点），只有校验失败和 `remove_model` 才删。
- 续传后校验失败 → 删掉从头再下一次（同一 URL 内），防止上游同名文件换版本。
- 进度 `on_bytes` 报绝对字节数，续传时不会从 0 跳。
- 测试服务器加 `Route::ranged()`（回 206 + Content-Range）与 `ranges()` 记录，新增 4 个用例：
  续传、服务器忽略 Range、满尺寸 `.part` 只校验、续传校验失败从头重下。34 个模型测试 + 全量 621 个通过。
- 文档同步：AGENTS.md 命令表、audiocpp-refactor.md §5.2、audiocpp-tasks.md P4-4 标记完成。

未做（可选）：`list_models` 暴露 `partial_bytes`，让未下载完的模型行能显示"继续下载 · 80%"。

## MAS 退回：llama-server 改走 Unix domain socket，去掉 network.server

背景：App Review 自动检查认为 App 声明了 `com.apple.security.network.server` 却没有对应功能。
根因是监听在子进程里（只在翻译期间存活），静态扫描看不到。

结论：
- `audiocpp_cli` 不需要该 entitlement（一次性 CLI，无 socket）。真正需要的是 `llama-server`。
- `llama-cli` 不是替代方案：一次进程一次生成，20 cue/批 → 每批重付 1.1 GB 模型加载，
  且丢 `cache_prompt`，输出是人看的（banner/timings），无稳定分隔协议。
- **正解**：`llama-server --host <path>.sock` 支持 UNIX socket（路径必须以 `.sock` 结尾）。

沙盒语义（已实测，非推测）：
- `/System/Library/Sandbox/Profiles/application.sb` 有
  `(allow network-bind network-outbound (resolving-subpath (param "application_container")))`，
  容器内路径的 bind 无条件放行；`network-server` 宏只是 `(allow network-inbound (local ip))`。
- 用 ad-hoc 签名的最小 `.app`（`app-sandbox` + 仅 `network.client`）实测：
  容器 `Data/tmp` 下 bind/listen/accept/收发全通；同一程序把 socket 放 `/tmp` → `EPERM`。
- **因此 socket 必须落在 `TMPDIR`（沙盒里 = 容器 `Data/tmp`）**，挪到 `/tmp` 会让翻译失效。
- 注意 `sandbox-exec` 的 `(deny network*)` 连 AF_UNIX bind 一起拒，与 App Sandbox 语义不同，
  不能拿它当近似模型。

实现：
- `translate/server.rs` 重写传输层：新增 `Endpoint::{Socket(PathBuf) | Tcp{port}}`；
  macOS/Linux 用 socket（`$TMPDIR/monosub-llama-<pid>-<seq>.sock`，长度>103 时退回 `ms-*.sock`），
  Windows 仍用回环 TCP（llama.cpp 的 AF_UNIX 仅 POSIX）。删除 `reserve_port`（unix）与 reqwest 依赖。
- 自带最小 HTTP/1.1 客户端：`Connection: close`，支持 Content-Length / chunked / EOF 三种 framing，
  纯函数 `parse_response` / `response_complete` / `decode_chunked` 都有单测。
- `Drop` 里 kill + unlink socket；启动失败也走同一条路径。
- `translate/mod.rs` 的 MockServer 改成同传输（unix socket；Windows 回环 TCP），
  `RemoteCompleter` 改为持有 `Endpoint`。
- 两个 entitlements 文件删掉 `network.server`，留注释说明"别加回来"。
- 修了 live-server 测试一直静默跳过的 bug（模型路径少了 `..`，实际指向 `src-tauri/models`）。

验证：629 个 lib 测试全过（含真实 llama-server 起 socket、`/health`、一次 completion、drop 后进程与
socket 文件都清掉）；`plutil -lint` 通过；clippy 无新增告警。**未做**：沙盒 pkg 真机跑一次翻译。

副产品：`prepare-resources.mjs` 用 `lib*.dylib` 过滤，把 `libllama-cli-impl` / `bench` / `perplexity` /
`quantize` / `fit-params` / `batched-bench` 等 llama-server 不加载的 dylib 也装进了 `bin/`（约 1 MB），
可收窄白名单。

## 模型下载不再校验清单 size / sha256（上游 master 换版导致装不上）

现象：`qwen3-asr-0.6b-f16` 报
`verification failed: '...qwen3-asr-0.6b-f16.gguf.part': expected 1880642016 bytes, got 1880649568`。

根因（已实测，非推测）：
- catalog 条目主 URL 是 `resolve/master`，`mirrors[0]` 才是固定 commit `67d0ca73`。
- ModelScope `master` 在 2026-10-20 被重传：1880649568 字节 / sha256 `490fefbe…`；
  固定 commit 仍是 1880642016 / `5472337d…`（与 catalog 完全一致）。
- `download_file` 原来把校验失败当终态，镜像明明可用也永远不试，模型永久装不上。
- `catalog::is_installed` / `list` 还要求 `size == file.size`，即使下下来也会显示"未安装"。

决策（用户指定）：不再校验字节与 hash，因为 URL 背后的 commit 本来就会变。

改动：
- `commands/models.rs`：删 `verify_file` / `sha256_file` / `hex_lower` / `HASH_BUFFER` /
  `DownloadError::Verify`；`download_file` 传输完成即 rename，size 不符只 `tracing::warn!`；
  返回实际写入字节数，`download_files` 用它累加进度基准。`transfer` 的 Range/206 逻辑不变
  （`.part` 与服务器总长不一致仍从头重下，避免把两个版本拼在一起）。
- `engine/catalog.rs`：`is_installed` / `list` 改为"文件存在且非空"，不再比 size。
- `sha2` 从 dependencies 挪到 dev-dependencies（只剩测试夹具用）。
- 测试：删 4 个 verify/sha 用例与 1 个"续传校验失败重下"用例，新增
  `download_accepts_a_file_larger_than_the_manifest_describes` /
  `download_accepts_a_sha256_the_manifest_does_not_describe`；两个测试改名不再提 verify。
- 文档：AGENTS.md 命令表、`docs/tech-spec/audiocpp-refactor.md` §5.2。

代价（已写进模块注释）：失去"上游同名换版本"与"内容被截断但 HTTP 正常结束"的检测能力；
`.part` 残留 + 新版本同长度的情况无法识别。

验证：`cargo test --lib` 623 passed / 1 ignored；`cargo check --all-targets` 通过（仅剩
`opener.rs::describe_status` 这条既有 dead_code 警告）。未真机重下一次 1.8 GB。

## 音频抽取：为何 0% GPU、为何慢、进度恒 0（实测，M4 / ffmpeg 9.0.2）

没有硬件加速，而且用不上：`transcribe.rs::ffmpeg_args` 里 `-vn` 直接丢视频流，
ffmpeg 根本不解码画面，`-hwaccel videotoolbox` 没有作用对象；ffmpeg 在 macOS 上
`-hwaccels` 只报 videotoolbox（视频编解码），音频解码没有硬件路径。全项目唯一用
videotoolbox 的是缩略图（`video.rs::hwaccel_args`，仅 macOS）。106% CPU ≈ 单核跑满
= 滤镜图单线程，0% GPU 正常。

耗时实测（10 分钟 48k 立体声 AAC → 16k mono wav）：

| 处理 | 耗时 | 折算 |
|---|---|---|
| 纯解码 + 重采样（无 `-af`） | 0.36 s | ~1660x |
| 现网滤镜链（loudnorm 跑在 48k 立体声） | 20.3 s | ~30x |
| 先 `aresample=16000,aformat=channel_layouts=mono` 再滤镜 | 9.4 s | ~64x |
| 去掉 loudnorm（只 highpass/lowpass/afftdn） | ~0.4 s | 巨大 |

结论：时间几乎全在 `loudnorm`（单遍动态模式，flags 为 `..`，不支持线程）；
`afftdn` 便宜。成本随 声道数 × 采样率 线性放大，所以把重采样/降混挪到滤镜链最前面
可 ~2x；换 `speechnorm` / `dynaudnorm` / 静态 `volume` 更快但会改 ASR 输入
（滤镜链是旧引擎 verbatim 移植，动之前要有识别结果对比）。

进度恒 0 的原因：`run_ffmpeg` 用 `Command::output()`，进程退出前 stdout/stderr 全缓冲，
无法增量读；调用处只有 `steps.begin(...,1)` 发一次 0%，下一次事件是 `steps.begin(...,2)`。
修法：`spawn` + `-nostats -progress pipe:1`，读 `out_time_us` / 总时长（stderr 的 `Duration:`
或 ffprobe）节流上报，需把 `&mut dyn ProgressSink` + task_id 透传进 `extract_wav`。
顺带：缓存命中应直接算 100%，失败重试不应让进度倒退。截图里的 "3m 6s" 是
`step_elapsed`（已耗时）不是 ETA。

## 抽取音频上报真实进度（先只做"进度"这一项）

用户选择：只做进度，不碰滤镜顺序/滤镜链（性能优化留待以后）。

后端 `commands/transcribe.rs`：
- `run_ffmpeg` 从 `Command::output()` 改为 `spawn` + 双管道，参数加 `-nostats -progress pipe:1`
  （`with_progress_args` 只在 `ffmpeg_args` 的 output 之前插入，抽取语义与 P0-9 测试原样不动）。
  这个改动之前，`output()` 把两个管道缓冲到进程退出，第 1 步在 0% 起跳到下一步之间不可能有事件。
- 分子 `out_time_us=`（每 `-stats_period` 0.5s 一块，`out_time_ms` 同为微秒）走 stdout；
  分母取 stderr 的 `Duration:` banner（不额外 ffprobe，避免分子分母来自不同流）；
  两条读线程用 `Arc<AtomicU64>` 汇合（谁先读到都可能）。
- `progress=end` 与最后一块都报 100%，重复值丢弃（`last_sent`）；`out_time=N/A` 不覆盖已知位置。
- `extract_wav` 在命中缓存、以及整段成功时显式报 1.0（`Duration: N/A` 的输入没有 tick）；
  `transcribe_file` 的闭包里做"只前进不回退"（滤镜链失败重试不会把条拉回 0）。
- 新增 `kill_on_drop(true)`：取消时不能留下孤儿 ffmpeg 继续写已删除的缓存 WAV。
- 纯函数 `parse_duration_banner` / `parse_timestamp` / `progress_fraction` + 5 个测试
  （含一个用假 ffmpeg 脚本跑 spawn→管道→解析→回调的端到端用例，assert `[0.25,0.5,0.75,1.0]`）。

前端：徽章原来显示 `overall`，而第 1 步只占 2% 权重，所以抽取三分钟也停在 "0%"。
- `StepProgress` 加 `percent`（步骤自身百分比），`App.tsx` 从 `event.payload.progress` 填；
  `FileItem` 徽章改用它，进度条/托盘仍读 `file.progress`（整次运行）。
- 代价：徽章每步归零一次（4 次），与进度条数值不同步。若不喜欢，正解是调第 1 步权重，
  不是把 `overall` 放回徽章。AGENTS.md §"Two percentages" 已按此重写。
