# 2026-10-25

## pnpm-workspace.yaml allowBuilds

- pnpm 12 在 install 时对未批准的构建脚本生成 `pnpm-workspace.yaml` 的 `allowBuilds` 占位符（`esbuild: set this to true or false`），install 会卡在这一步，`node_modules/esbuild` 缺失。
- 结论：`esbuild: true`。Vite 依赖 esbuild 的 postinstall（`node install.js`）放置平台二进制（Windows 下为 `@esbuild/win32-x64`），设为 false 会导致 vite dev/build 报 "installed for another platform"。
- 已改并验证：`pnpm install` 通过，`node_modules/.pnpm/esbuild@0.25.12/node_modules/esbuild/bin/esbuild` 已生成。
- **后续（同日修正）**：`pnpm-lock.yaml` / `pnpm-workspace.yaml` 已删除。原因不是 esbuild 配置，而是它们让 Tauri 报了版本不匹配：pnpm 锁把 `@tauri-apps/plugin-dialog` 解析到 2.8.3、`plugin-notification` 解析到 2.7.0，而 `bun.lock` 与 Rust crate 还在 2.6.0 / 2.3.3。`tauri` 只警告后仍按 bun 安装，于是 `node_modules` 与 `Cargo.lock` 各说各话，`tauri build` 直接失败。
- 结论：项目只用 **bun**（`bun.lock` 是唯一锁文件，`scripts/windows/build-msix.sh` 也跑 `bun install`，`tauri.conf.json` 的 beforeBuildCommand 是 `bun run build`）。两边版本已对齐到 dialog 2.8.3 / notification 2.7.0；`pnpm` 的文件不要再加回来。

## release / publish 拆分（scripts）

- 用户要求把「构建产物」和「发到 GitHub」分开。现状：`scripts/release/release.sh` 既构建又 `gh release create`，`scripts/windows/release-msix.ps1` 既 build 又上传。
- 新约定：**release = 只在本地产出 dist/ 里的产物（不联网）**；**publish = 只把 dist/ 里的文件上传到 GitHub Releases（不构建）**。
  - `scripts/release/release.sh`：读版本 → 调 `build/build-macos-app.sh` → 收集核对 DMG；`--skip-build`（`--skip-package` 为兼容别名）。不再调 gh、不再 bump。
  - `scripts/publish/publish.sh`（新）：`--version` / `--recreate` / `--add-assets` / `--skip-bump` / `--draft` / `--asset` / `--notes-file`。
  - Windows：`build-msix.ps1` = release，新增 `scripts/windows/publish-msix.ps1`（`-Tag` / `-Version` / `-UpdateTag`），删掉 `release-msix.ps1`。
  - `bump-version.sh` 从 `scripts/release/` 移到 `scripts/utils/`，只在 publish 成功后调用。
- 关键不变量：**tag 必须严格等于 `v<tauri.conf 版本>`**（App 用 `CARGO_PKG_VERSION` 跟 tag 比），所以版本自增必须发生在发布之后，否则会重现 tag v2.0.0 / 产物 MonoSub-2.0.1.dmg。
- publish 认「产物版本」而非配置版本：上一轮发布已把 tauri.conf 自增，跨平台补资产时用 `--version`/`-Version` 指定；扫 dist 时若没有文件名含该版本的文件就硬失败，防止把旧产物挂到新 tag。
- package.json 新增 `release:dmg` / `publish:macos` / `publish:msix`；README(scripts)、AGENTS.md、Store 规范里的引用已同步。

## MSIX 身份（回答过的问题，留档）

- MSIX 装不到自选目录：固定 `C:\Program Files\WindowsApps\...`，清单无此字段。要「安装时选目录」只能换 NSIS（Tauri 模板第 5 页 `MUI_PAGE_DIRECTORY`）或自定义 WiX。
- 三个容易混的东西：`Package/Identity/Publisher`（DN，必须=签名证书 Subject，Store 版必须=Partner Center 给的值）、由它算出的 **PublisherId**（13 字符，SHA-256(UTF-16LE DN) 前 8 字节 Base32，字母表去 i/l/o/u，末位 4 bit 左对齐）、`PublisherDisplayName`（仅显示）。
- 当前包（`dist/monosub_2.0.0.0_x64.msix`）：`Identity Name="monosub" Publisher="CN=leix"`，PublisherId = `mhvf1em81qtn2` → PFN `monosub_mhvf1em81qtn2`，安装目录 `...\monosub_2.0.0.0_x64__mhvf1em81qtn2`，包数据 `%LOCALAPPDATA%\Packages\monosub_mhvf1em81qtn2`。
- `dev.leix.monosub` 是 Tauri `identifier`（反向 DNS，正常），**不进 MSIX 清单**；它只决定 macOS bundle id、`app_data_dir`（`%APPDATA%\dev.leix.monosub`）等。
- 上架前必改：`MONOSUB_MSIX_NAME` / `MONOSUB_MSIX_PUBLISHER`（= Partner Center 的 Package/Identity 值）。`PublisherDisplayName` 目前在 build-msix.ps1 里硬编码 `'leix'`，没走 env。
