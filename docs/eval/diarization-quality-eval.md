# 说话人分离质量评测：`attribute_cues` 改动的实测验证

> 状态：**已完成**（真实素材，4 小时双人对谈）
> 执行日期：2026-10-23，Apple M4 / macOS arm64
> 关联：[`engine/diar.rs`](../../src-tauri/src/engine/diar.rs) `attribute_cues`、
> [`AGENTS.md`](../../AGENTS.md) 说话人标签小节、
> [`audiocpp-accuracy-p1-23.md`](../tech-spec/audiocpp-accuracy-p1-23.md)（同类的实测文档）

---

## 1. 为什么需要这份文档

`AGENTS.md` 与 `diar.rs` 的注释里有一条**未经独立验证**的因果声明：

> 一个 VAD chunk 最长 15 秒，跨过说话人切换时整块只能给一个标签，所以
> `attribute_cues` 必须在 cue 粒度上重新归属。

这句话在代码层面成立，但「改完之后真的更准了吗、准多少」从来没有被量化过。
`diar.rs` 的单元测试用的是构造数据，只能证明**逻辑**正确，不能证明**效果**。

这次恰好有一次天然的对照实验：同一个 4 小时访谈文件，改动前后各跑了一遍，
产物都在盘上。于是可以用它把「效果」也测出来。

**结论先行：cue 级归属确实有效，整体标签准确率 93.90% → 99.85%，
主持人提问被误标为嘉宾的比例 30.77% → 0.67%。**

## 3. 评测方法

### 3.1 为什么不能「互相比较」

两个文件分歧 323 条，但分歧本身不说明谁对。需要**外部真值**。
本机没有人工标注，所以真值从音频本身重建，用**四个互不相关的判据**。

### 3.2 判据一：基频（f0），逐帧自相关

两位说话人的音高分离得非常干净，这一点先要确认，否则后面全部失效：

```
逐帧 f0 直方图（16 kHz，50 ms 窗 / 10 ms 跳，自相关法，共 661 364 个浊音帧）

  70–150 Hz  ███████████████████████████████████  66.6%  嘉宾 B
 150–165 Hz ████                                  6.6%  （过渡带）
 165–400 Hz ██████████████                       26.8%  主持人 A
```

细看主峰：嘉宾集中在 **80–100 Hz**（全局最大值在 90 Hz 档），
主持人集中在 **190–230 Hz**。按 cue 取中位数：主持人 ≈ **205 Hz**
（p10 180 / p90 239），嘉宾 ≈ **113 Hz**（p10 94 / p90 152）——相差约 1.8 倍。

过渡带 150–165 Hz 只占 6.6%，不是「几乎为零」，所以阈值判据在边界附近
会出错；这也是后面要用帧级构成（§3.3）和嵌入（§3.4）交叉验证，
而不是单靠一个阈值的原因。

### 3.3 判据二：帧级 f0 构成

判据一给出的是「这一整条 cue 的**中位**音高」。但一条 cue 里可能真的有两个
说话人（估时把两句话并进了一段），此时中位数会骗人。
所以再算每条 cue 内**有多少帧落在 A 频段、多少帧落在 B 频段**：

```python
Afrac = frames in [160, 320] Hz / voiced frames
Bfrac = frames in [ 70, 150] Hz / voiced frames
```

- `Afrac > 0.85` 或 `Bfrac > 0.85` → 单一声源，可信
- `0.25 < Afrac < 0.75` → **帧级混合**，这条 cue 本身就跨说话人，任何单一标签都不完全对

### 3.4 判据三：ECAPA 说话人嵌入（**无监督**）

前两个判据都依赖音高，属于同一族方法，可能同错。所以加一个**原理完全不同**的：
[`speechbrain/spkrec-ecapa-voxceleb`](https://huggingface.co/speechbrain/spkrec-ecapa-voxceleb)
的 192 维 x-vector，余弦相似度判人。

关键是**不能拿任何一个文件的标签做种子**，否则就是循环论证。做法：

1. 只取时长 ≥ 2.0 s 的 cue（2611 条），**完全不看标签**
2. 对嵌入向量跑 k-means（k=2），得到两个聚类中心
3. 两个中心的余弦相似度 **0.393**（同人应接近 1.0），确认确实是两个人
4. 少数派聚类（402 条）即主持人 —— 这与「主持人只占 15.6% 音频时长」吻合
5. 再用这两个**无监督中心**给所有 cue 打分

独立锚点校验：取片头 1–7 条（主持人自我介绍，必然是他）与 9、11–16 条
（嘉宾回答，必然是他）各自求中心，两中心余弦 **0.154**，分离度更高。
锚点对争议 cue 的判定与无监督 k-means 的一致率 **98.1%**。

### 3.5 判据四：纯文本（不看音频）

最后再加一个**完全不碰音频**的判据，用内容特征：

- 主持人：`你…吗 / 你…什么 / 为什么 / 对吧 / 是不是 / ？`
- 嘉宾：`我觉得 / 我认为 / 我当时 / 我出生 / 我(在|是|的) / 嗯，…`

这个判据只能覆盖 555/4154 条（大多数 cue 没有强特征词），但它的价值在于
**失败模式和声学判据完全无关**。

### 3.6 真值构建与评测集

四个判据各自能覆盖一部分 cue，取**至少两个判据一致**的 cue 作为真值集：

| 集合 | 规模 | 说明 |
|---|---|---|
| 至少 2 判据一致 | **3310** | 主评测集 |
| 声学 + 文本**都**能判且一致 | **279** | 严格集，最干净 |

严格集里文本/声学冲突率 **0.0%**，说明这两个独立判据在可判 cue 上完全一致。

## 4. 结果

### 4.1 主评测集（3310 条，≥2 判据一致）

| 文件 | 归属逻辑 | 正确 | 准确率 | 错误数 |
|---|---|---|---|---|
| `EP_YaoShunyu_4h.srt` | **cue 级**（新） | 3305 | **99.85%** | 5 |
| `EP_YaoShunyu_4h-v1.srt` | chunk 级（旧） | 3108 | 93.90% | 202 |

差距 **5.95 个百分点**，bootstrap（2000 次重采样）95% 置信区间 **[5.17, 6.80]**。

两文件在评测集内分歧 201 条：**main 对 199 条，v1 对 2 条。**

### 4.2 严格集（279 条，文本与声学都判且一致）

| 文件 | 正确 | 准确率 |
|---|---|---|
| `EP_YaoShunyu_4h.srt` | 278 | **99.64%** |
| `EP_YaoShunyu_4h-v1.srt` | 222 | 79.57% |

严格集内分歧 56 条：**main 对 56 条，v1 对 0 条。**

严格集的准确率绝对值比主集更低，是因为它的构成极度偏斜：**279 条里 182 条是
主持人 A，且这 182 条全部是带「？」的提问**（主集里 A 只占 15.2%）。
它本质上是在测「主持人提问」这一个最难、也最该对的子集——
而那正是 v1 的弱点（见 §5）。

### 4.3 按说话人拆解 —— 错误极不均衡

|  | 主持人 A 说话时 | 嘉宾 B 说话时 |
|---|---|---|
| main | 2 / 503 = **0.40%** | 3 / 2807 = 0.11% |
| v1 | 129 / 503 = **25.65%** | 73 / 2807 = 2.60% |

**主持人提问（含「？」且真值为主持人）被误标成嘉宾：**

| 文件 | 错误率 |
|---|---|
| main | 2 / 299 = **0.67%** |
| v1 | 92 / 299 = **30.77%** |

### 4.4 按 cue 时长拆解

| cue 时长 | n | main 错误率 | v1 错误率 |
|---|---|---|---|
| < 0.7 s | 22 | 4.55% | 18.18% |
| 0.7–1.5 s | 591 | **0.17%** | **10.66%** |
| 1.5–3.0 s | 1348 | 0.15% | 6.68% |
| 3.0–6.0 s | 1099 | 0.09% | 3.55% |
| ≥ 6.0 s | 250 | 0.00% | 2.40% |

v1 的错误在 0.7–1.5 s 区间最严重（10.66%）。短句正是主持人的典型发言长度
（「多频繁？」「为什么？」「几个人？」），与 §4.3 的结论一致。

## 5. 错误机制：为什么 v1 会这样错

不是随机噪声，是一个**可解释的系统性偏差**。

主持人只占 **15.6%** 的音频时长（34.6 min / 222.4 min），嘉宾占 84.4%（187.8 min）。
一个 VAD chunk 最长 15 s，一旦跨过「主持人问 → 嘉宾答」的边界，
**块内多数派永远是嘉宾**，整块就被判给嘉宾。主持人每次只插一句话，
所以他受这个 bug 的伤害是嘉宾的 **10 倍**（25.65% vs 2.60%）。

结构证据同样支持：

| 指标 | main | v1 |
|---|---|---|
| 标签切换次数 | **955** | 533 |
| 标签运行段数 | 956 | 534 |
| 最长连续同标签 | 48 条 | 54 条 |

v1 的切换次数少了 44%，说明它把大量「主持人问 / 嘉宾答」的轮次**粘成了一整段**。
main 的 cue 数反而更多（4229 vs 4184），也正是因为 `merge_short` 现在是
speaker-aware，不再跨说话人合并短句。

### 5.1 一个反直觉的实测细节

`diar.rs` 注释里引用的 motivating bug 是第 10 条
「这对于其他模型公司很难吗？」。它在 main 里**标签是对的**（A），
但它的**估算时间区间** `44.057–46.687 s` 实际落在**嘉宾的语音**上：

```
cue 9  39.486–44.057   A=3  B=7   ← 嘉宾说话，末尾 3 个点已是主持人
cue 10 44.057–46.687   A=0  B=5   ← 全在嘉宾语音上，但文本是主持人提问
cue 11 46.687–50.287   A=0  B=7   ← 嘉宾回答
```

原因：这个文件走的是 `qwen3_asr` 的**估算时间**路径（无 `--words-out`），
cue 的时间边界是按字符数比例摊的，不是测出来的。所以**文本内容与时间轴可以对不上**。

这件事的两个后果：

1. 声学判据若只看 cue 的**时间区间**，会把这条 cue 判成嘉宾 —— 这是**判据的**
   局限，不是文件的错误。因此主评测集用「≥2 判据一致」做门控，
   把这类时间轴漂移的 cue 排除在真值之外（它们进不了评测集，不会污染分数）。
2. **标签质量 ≠ 时间轴质量。** 本次改动只动标签，`-v1` 和 main 的
   时间轴**完全一样**（4093 条 `(start,end)` 逐位相同）。要修时间轴漂移，
   得开词级时间戳（`qwen3_asr` + forced aligner），是另一个改动。

## 6. main 剩下的 5 处错误

不是全部完美，逐条列出以便判断是否值得继续修。四个判据各自的投票：

| # | 时长 | 真值 | main | 帧级 A% | onset | 无监督 | 文本 | 文本内容 |
|---|---|---|---|---|---|---|---|---|
| 393 | 2.7 s | A | **B** | 90% | B (.17) | A | A | 我不理解，什么叫你不理解？ |
| 1235 | 0.6 s | B | **A** | 100% (n=15) | B (.22) | B | — | 嗯啊。 |
| 2361 | 2.2 s | A | **B** | 83% | A (.35) | A | A | 三点七，三点七，还是三点五六？ |
| 2703 | 0.9 s | B | *None* | — | B (.21) | B | — | Yeah. |
| 4014 | 4.7 s | B | **A** | **47% / 51%** | B (.47) | B | — | 我现在最高优先级是就是把我刚才说的这两个事情能够，能够把它。 |

逐条说明（**区分实测与推测**）：

- **#2361 是唯一一个四个判据完全一致、main 却判错的 cue。**
  83% 的帧落在 A 频段，文本是典型的主持人追问，两个声学判据都给 A
  （conf 0.35 / 0.59），main 给了 B。这是一次真正的归属错误，成因无法从
  产物反推（`turns.json` 在转写结束时已被删除），只能记录现象。
- **#393 是边界 cue。** 整条 cue 的帧级构成 90% 是 A，但**开头 0.9 s** 的
  onset 判据给了 B（conf 仅 0.17）——说明这条 cue 的起始边界**蹭到了上一位
  说话人的尾音**。main 的归属落在 B，很可能是 turn 重叠恰好压在了那一段尾音上。
  这不是「主持人复述嘉宾」那类内容难点（帧构成证明它就是 A 在说），
  而是**估时边界不准**的连带后果。
- **#1235「嗯啊。」** 0.6 s，只有约 15 个浊音帧，帧级判据几乎无信息量；
  两个声学判据都判 B（0.22 / 0.39），main 给了 A。属于短填充词上的真实错误。
- **#2703「Yeah.」** main 给的是 **`None`（完全没有标签）**，不是标错。
  这条 cue 没有与任何 diar turn 重叠，而 `attribute_cues` 的既定行为是
  「没有重叠就保留原有标签」——它原本就是 `None`，于是保持 `None`。
  这是 §设计里「gap 不是换人的证据」的**已知取舍**，不是 bug。
- **#4014** 是 4.7 s 长句，帧级构成 **A 47% / B 51%** —— 真正的跨说话人 cue，
  单一标签必然错一半。任何归属逻辑都无法把它标对。

所以 5 条里：**1 条是真正的归属错误（#2361），1 条是估时边界连带（#393），
1 条是短填充词（#1235），1 条是已知的 gap 取舍（#2703），
1 条在原理上无法标对（#4014）。**

### 6.1 v1 唯一对而 main 错的 2 条

| # | 时长 | 真值 | 文本 | 性质 |
|---|---|---|---|---|
| 1235 | 0.6 s | B | 嗯啊。 | 短填充词，main 判 A |
| 4014 | 4.7 s | B | 我现在最高优先级是就是把我刚才说的这两个事情能够，能够把它。 | 帧级混合，main 判 A |

两条都已在 §6 表里，且都不是「main 的系统性缺陷」：一条是 0.6 s 的填充词，
一条是 4.7 s 的混合 cue。相对 3310 条的评测集，占比 0.06%，
不足以改变结论。

## 7. 复现步骤

依赖：`uv`、`ffmpeg`、以及已生成的 `<stem>_audio.wav`（App 首次转写时自动产出）。

```bash
# 1) 声学依赖
uv venv .venv && uv pip install --python .venv/bin/python numpy soundfile scipy
uv venv .venv311 --python 3.11
uv pip install --python .venv311/bin/python torch torchaudio speechbrain numpy soundfile

# 2) 解析两个 SRT（按 (start,end) 对齐，而不是按行号 zip）
# 3) 逐帧 f0 + 帧级 A/B 构成
# 4) ECAPA 无监督 k-means（只用 >=2.0 s 的 cue，不看标签）
# 5) 文本特征判据
# 6) 取 >=2 判据一致的 cue 做真值集，再分别给两个文件打分
```

四个关键实现细节（都是踩过的坑）：

1. **对齐必须用 `(start, end)` 做 key，不能用行号 `zip`。** 两文件 cue 数不同
   （4229 vs 4184），按行号对齐会在第一个插入点之后全部错位，
   我曾因此得出「只有 296/4184 条时间相同」的错误结论。
2. **ECAPA 的参考中心绝不能来自任一文件的标签。** 否则测的是
   「文件与自己的吻合度」，必然接近 100%。
3. **音高判据要防八度错误。** 男声的二次谐波会落在女声频段内，
   所以要用自相关峰 + 中位数收敛（`f0/1.6 < f0 < f0*1.6`）把离群值剔掉，
   并且只在**浊音帧**上统计。
4. **不要把「时间区间」当成「文本内容」的真值。** 见 §5.1，
   估时路径下两者可以不一致。

## 8. 结论与后续

**已验证：**

- `attribute_cues` 的 cue 级归属是有效的，整体标签准确率 **93.90% → 99.85%**。
- 收益**高度集中在主持人**（25.65% → 0.40%），这正是设计预期的形状——
  chunk 级归属对「短插入、被长块吞并」的少数派说话人伤害最大。
- 收益与 cue 时长正相关，短句（0.7–1.5 s）改善最明显（10.66% → 0.17%）。
- `merge_short` 改成 speaker-aware 是必要的：否则跨说话人的短句会先被合并，
  再贴标签，边界就丢了。两个改动必须同时存在。

**未覆盖 / 已知局限：**

- **时间轴漂移未修。** 本文评测的是**标签**，时间轴两个文件完全相同。
  估时路径下「文本 vs 时间区间」不一致是常态（§5.1），要修需要词级时间戳。
- **只测了一段素材**（1 位主持人 + 1 位嘉宾，中文，3.8 h）。
  多人（≥3）场景、英语、快速抢话的场景没有覆盖。
- **真值集排除了帧级混合的 cue**（约 14.7%）。这些 cue 本来就无法用单一标签
  正确表达，是 `diar` 模型 + 后处理的结构性上限，不在本次改动的范围内。
- **`turns.json` 在转写结束时被删除**（`commands/transcribe.rs` 的既定清理），
  所以残余错误只能从 SRT + 音频反推，无法逐条对照 diarizer 的原始 turn 区间。
