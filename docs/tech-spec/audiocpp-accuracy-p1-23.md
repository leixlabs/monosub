## 1. 为什么还需要这份文档

Phase 0 的 Go 结论是**附条件**的，唯一缺口是「中文准确率主观不劣」未验证（PoC §6.1）。
本次用**同一段音频**同时跑旧引擎（FunASR）与新引擎（audio.cpp），给出可比数据。

**重要局限**：本机没有真实评测素材（≥1h 长音频 / 多人对话 / 中英混合），
语料由 macOS TTS（`say -v Tingting`）合成。合成语音**比真实语音更干净**，
因此本结果**不能**替代真实素材验收，但足以回答「两引擎是否同源同质」以及
**验证 VAD 参数**（P1-23 明确要求，PoC §4.3 也建议）。

## 3. 结果

### 3.1 字符相似度（去标点后，对全量真值）

| 引擎 / 配置 | 字符相似度 |
|---|---|
| FunASR（现状，MPS） | 97.2% |
| audio.cpp，`padding=0.25 gap=0.5`（**spec 默认**） | 97.6% |
| audio.cpp，`padding=0.10 gap=0.2` | 97.6% |

**结论：两者同质，无劣化。** 词级错误相同（`Kubernetes`→`Qubbernet`/`ubbernet`、
`gRPC`→`GRTC`），属于 SenseVoice 模型本身的专有名词弱点，**不是引擎替换引入的**。
数字与 ITN 两者都正确（`二零二四`→`2024`、`百分之四点九`→`4.9%`）。

### 3.2 速度与内存

| 指标 | FunASR（现状） | audio.cpp |
|---|---|---|
| wall time（35.59s 音频） | 8.07s（含模型加载） | **1.06s** |
| 峰值 RSS | ~3 GB（PoC §5 实测 2.9–3.0 GB） | **560 MB** |

与 PoC §5 一致：快约 2x、省内存约 5x。

### 3.3 分段边界（关键差异）

**spec 默认 `padding=0.25 / merge-gap=0.5` 会把 4 句并成 3 段**，并产生错位文本：

```
[  0.00- 13.57] 根据国家统计局发布的数据，2024年第三季度国内生产总值同比增长4.9%。，我们需要在Qubernet集群上部署一个新的微服务。
[ 13.57- 28.10] 使用GRTC进行通信请问从北京南站到首都国际机场坐地铁大概需要多长时间，会不会堵车？会议纪要？
[ 28.10- 35.10] 第一，确认预算。第二，调整排期。第三，下周提交设计稿。
```

注意 `会议纪要？` 被**错位**到上一段末尾（真值中 `会议纪要：` 属 u4）。

`padding=0.10 / gap=0.2` 则 4 句正确切分，且文本更干净：

```
[  0.00-  8.61] 根据国家统计局发布的数据，2024年第三季度国内生产总值同比增长4.9%。
[  9.09- 17.67] 我们需要在ubbernet集群上部署一个新的微服务，使用GRTC进行通信。
[ 18.21- 26.37] 请问从北京南站到首都国际机场，坐地铁大概需要多长时间，会不会堵车？
[ 26.91- 34.95] 会议纪要第一，确认预算。第二，调整排期。第三，下周提交设计稿。
```

### 3.4 机制（已用参数扫描证实）

`padding p` 把每个语音区间**两侧各外扩 p 秒**，于是原始间隔 `g` 缩短为 `g − 2p`；
当 `g − 2p < merge_gap` 时两段被合并。spec 默认下：

```
g = 0.8s,  p = 0.25  ->  0.8 − 0.5 = 0.30s  <  merge_gap 0.5s   => 合并
```

参数扫描（同一音频，均应为 4 段）：

| padding | merge-gap | 实际段数 |
|---|---|---|
| 0.25 | 0.5 | **3** ❌ |
| 0.25 | 0.2 | 4 ✅ |
| 0.10 | 0.5 | 4 ✅ |
| 0.10 | 0.2 | 4 ✅ |
| 0 | 0.5 | 4 ✅ |

**判读**：spec 默认组合等价于「原始停顿 < 1.0s 就合并」。朗读/结构化语音的句间停顿常 < 1.0s，
因此**默认值倾向于过度合并**。后果不是丢字，而是**边界漂移**（如上面 `会议纪要？` 归属错误），
以及后处理按标点重新切句时的时间轴错位。

> 与 PoC §4.3 的观察一致：padding 是**质量相关**参数，不只是对齐参数。

## 4. 结论

1. **准确率：无劣化。** 字符相似度 97.2%（FunASR）vs 97.6%（audio.cpp），错误同源。
2. **速度/内存：明确更优**（1.06s vs 8.07s；560MB vs ~3GB）。
3. **VAD 常量需要调**：spec 默认 `padding=0.25 / merge-gap=0.5` 会过度合并相邻语句。
   建议改为 `padding=0.10 / merge-gap=0.2`（本机 4/4 正确切分，相似度不降，且停顿 < 0.4s 才合并）。
   代码中已是单一常量（`engine/vad.rs` 的 `VAD_PADDING_SECONDS` / `VAD_MERGE_GAP_SECONDS`），改动为一行。
