# 2026-10-28

## DMG 安装窗口：根因定位与确定性修复

**结论**：`bundle.macOS.dmg` 的配置本身是对的（背景图、660×400、图标位置），问题出在
create-dmg 的 AppleScript 收尾：只要传了 `--background`，它就会执行

```applescript
set position of every item to {theBottomRightX + 100, 100}
```

`.VolumeIcon.icns` / `.background` 被停到窗口右外 100pt。macOS 26 上 Finder 有两种反应，
都是可见缺陷：把窗口撑大（实测 908×595，背景只铺左上角，卷图标落进窗口 →
"图标重复"），或维持 660×400 但画出滚动条（图标视图内容比视图宽）。
`+100` 相对窗口自身右边界，所以**任何 windowSize 都躲不掉**，配置层无解。

另外发现：窗口几何会受 Finder 记住的该卷窗口状态影响（我调试时反复挂载的同名卷
导致过一次 908×595），所以结果**不是可复现的** —— 这正是需要确定性后处理的原因。

**做法**：官方流程照旧（Tauri + create-dmg 出 DMG），之后加一步纯字节修补：

- 新增 `scripts/release/polish-dmg.mjs`：UDRW 转换 → 挂载 → `chflags hidden`
  → 原地改 `.DS_Store`（bwsp.WindowBounds、`.app`/`Applications` 的 Iloc、
  点开头条目的 Iloc 收回窗口内）→ 重新 UDZO。只做等长字节替换，不碰 Bud1 偏移表，
  不经过 Finder，约 2 秒。
- `package.mjs` 第 7b 步调用它；`verify.mjs` 新增 `verifyDmgWindow()` 断言窗口尺寸、
  图标位置、无越界条目、隐藏标记 —— 失败即中止构建。

**`.DS_Store` 记录格式的坑**（写解析器时要记住）：记录没有 record_length 字段，实际是
`u32 名字字符数 + 名字(UTF-16BE) + code(4) + type(4) + u32 数据长度 + 数据`；
名字只能靠向前扫描匹配长度前缀反推，且必须用 UTF-16**BE**（Node 没有 BE 解码器，
要 `swap16()` 后用 utf16le）。`bwsp.WindowBounds` 的 y 是**左下原点**，
反推屏幕高度 = `y + height + 窗口顶部 y`。

## 背景图

`scripts/release/make-dmg-background.py`（Pillow，开发期工具，不参与打包）生成
`src-tauri/dmg/background.png`：1320×800 = 660×400 @2x，Finder 按 1 图像像素 =
1 设备像素绘制。**不放任何自然语言文案**（应用是中英双语，硬编码中文会在英文环境乱入），
只有品牌名 + 两图标之间的箭头 —— Tauri 官方文档也是这么建议的。
图标行 y 从 170 调到 200，让「标题下留白」和「标签下留白」对称。

坑：`qlmanage -t -s 1320` 渲染 SVG 会丢文字并补成正方形画布，不能用；
Pillow 直接画才是可控的。

## 验证手段

IDE 窗口总盖住 Finder 窗口，`screencapture -R` 抓不到。可靠办法是按窗口 ID 截图：
`pyobjc-framework-Quartz` 列 `CGWindowListCopyWindowInfo` 找 Finder 窗口，
再 `screencapture -x -o -l <windowid>`。脚本见 `/tmp/shotwin.py`（临时）。
