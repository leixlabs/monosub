## 打包 + 安装 MonoSub，并排查"安装成功退出但什么都没装"

完整记录见 `monosub\.dsh\projects\win-installer-integrity\INSTALL-TROUBLESHOOTING.md`。
### 一句话根因

`C:\Users\lei\Projects` 整个目录树带着 **Low 强制性完整性标签**
（`icacls` 显示 `Mandatory Label\Low Mandatory Level:(OI)(CI)(NW)`，Codex 沙箱工具遗留）。
Windows 让进程继承"它被启动的那个文件"的完整性级别，所以从 `dist\` 启动的 NSIS 安装器
进程是 Low，而 Low 不能写 `%LOCALAPPDATA%` / `%APPDATA%` / `HKCU`（默认 Medium）：

- 双击 GUI：向导走到 `Output folder: %LOCALAPPDATA%\MonoSub` 卡住，目录不建，无报错。
- `/S` 静默：**3 毫秒 exit code 0**，什么都不写。退出码 0 是最有欺骗性的地方。

**与安装包无关**。同一份字节复制到 `%TEMP%` 再跑，78 秒装好 84 个文件 / 2025.6 MB，
快捷方式和卸载项齐全；A/B 探针（写 `%LOCALAPPDATA%`+`HKCU`）只换位置就
FAILED/FAILED → ok/ok。签名的 notepad/node 放进项目树也变 Low、放进 Downloads 是 Medium
—— 变量是路径，不是签名/二进制。

### 修复

1. 环境（已执行）：`icacls "C:\Users\lei\Projects" /setintegritylevel "(OI)(CI)Medium" /T /C`
   → 118748 个文件，0 失败，83.8s。修复后项目树 exe 启动级别 = Medium。
2. 代码（新增）：
   - `scripts/release/check-integrity.mjs` — 检测 + `--fix`
   - `scripts/release/install.mjs` — 复制到 `%TEMP%` 再装 + 校验文件树/卸载项/快捷方式
   - `installer.mjs` — 打包时 `checkIntegrityLevel()` 警告
   - `package.json` — `release:install` / `release:integrity`

### 验证（全部实测）

- `bun/npm run release:install`：84 文件 / 1.98 GB，卸载项 `MonoSub 2.1.0`，开始菜单
  + 桌面快捷方式齐全；应用启动，窗口 `MonoSub`，WebView2 正常，UI 截图完整。
- 随包运行时：yt-dlp `2026.08.19`、ffmpeg `n8.1.3`、audiocpp_cli、llama-server、
  monosub-cli `--list-models` 全部正常 —— 之前 `.memory` 里 yt-dlp 的
  `Could not create temporary directory!` 其实是同一个 Low 标签根因。
- 卸载回归：应用运行时 `--uninstall` 自动 taskkill + 轮询等异步删除，0 退出、目录清空。
- 全量打包：`installer.mjs --skip-resources` 成功产出 1.31 GB 有效安装包（LZMA ~7 分钟）。

### 踩坑

- `Start-Process -Wait` 遇到 GUI 安装器会挂；用 `System.Diagnostics.Process` +
  `UseShellExecute=$false` 自己轮询 `HasExited`。
- NSIS 卸载器是异步的（复制到 `%TEMP%\~nsu*.tmp\Un.exe` 重启），退出码 0 ≠ 删干净。
- PowerShell 后台任务里，node 往 stderr 写一行（如 DeprecationWarning）会被报成
  `exit code 1`，即使 node 真 exit 0 —— 用 `$LASTEXITCODE` 或看 stdout 判断。
- **更正上游一条老结论**：第一轮记录的 yt-dlp `Could not create temporary directory!`
  当时归因为 TMP/TEMP 变量或杀软；本轮实测真正根因就是上面的 Low 完整性标签
  （bootloader 在 `%TEMP%` 建 `_MEI<pid>` 也需要 Medium）。`verifyYtDlp()` 的兜底
  仍有用（不干扰），但根因已修。

## 修复 `bun run release:exe` 在 yt-dlp 冒烟测试处失败

症状（`release:exe` → `prepare-resources.mjs` → `smokeTestWindows()`）：

```
[PYI-27076:ERROR] Could not create temporary directory!
[ERROR] ...\resources\bin\yt-dlp-x86_64-pc-windows-msvc.exe exited with code 4294967295
[ERROR] C:\Program Files\nodejs\node.exe exited with code 1
error: script "release:exe" exited with code 1
```

根因：随包的 `yt-dlp.exe` 是 PyInstaller 单文件构建。Python 启动前，bootloader
先 `GetTempPathW()`（先 TMP 后 TEMP），再 `CreateDirectoryW("<temp>\_MEI<pid>xxxxxx",
带"仅当前用户"DACL)`；五次都失败就打上面那行并以 `0xFFFFFFFF` 退出（Node 显示
`4294967295`）。下载与 SHA-256 校验都没问题 —— 是**临时目录**建不出来，而不是
二进制坏了。注意这与"普通 mkdir 失败"不完全等价：DACL 限制在 FAT32/exFAT、
网络盘、部分重定向 profile 上会单独失败，所以只能拿真 exe 去试。

改动：

- `scripts/lib/shell.mjs`：新增 `runCaptured()`（返回 `{ code, output }`，不抛），
  用来读 bootloader 原文。
- `scripts/release/prepare-resources.mjs`：新增 `verifyYtDlp()`，替换两处
  `run(yt-dlp, ['--version'])`。按 继承的 TMP/TEMP → `%LOCALAPPDATA%\Temp` →
  `build\pyi-tmp` 逐个**实际运行**，记住能用的 env（`ytDlpEnv`，声明在 `main()`
  调用之前避免 TDZ）；全失败时抛错并列出每个候选的退出码与原文。
- `src-tauri/src/paths.rs`：新增 `pyinstaller_temp_dir()`（Windows），系统 temp
  探针失败时退到 `%LOCALAPPDATA%\leixlabs.monosub\tmp`（再退 `%USERPROFILE%\.monosub-tmp`）；
  `can_create_directory()` 做 create/remove 探针，附单测。
- `src-tauri/src/site/ytdlp.rs`：spawn 前按需注入 `TMP`/`TEMP` —— 打包后的应用
  走同一条路，所以 `--skip-resources` 不是解法。
- `scripts/README.md`：加"yt-dlp 的临时目录"一节。

验证（本机 Linux 沙盒，无法跑 Windows 构建）：`node --check` 两个 .mjs 通过；
把模块的 `main()` 摘掉后直接调 `verifyYtDlp()`，用假 exe 复现四种情况 ——
继承目录可用（无警告、不建 build/pyi-tmp）、继承目录坏→`%LOCALAPPDATA%\Temp`、
两者都坏→`build\pyi-tmp`、全坏→聚合报错并 exit 1。Rust 侧本机无 cargo，未编译。

若三个候选都失败：属于环境（杀软拦 `_MEI*`、TMP 指向非 NTFS/网络盘、策略限制），
需要加排除项，脚本已把每个候选的真实退出码和 bootloader 原文打出来。
