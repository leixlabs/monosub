## 17:15 排查：VAD 阶段 `failed to read WAV data chunk`（缓存 WAV 被取消的 ffmpeg 写坏）
- 现象：录制 steno-merged-1080p.mp4（589MB，747.28s）转写，`audiocpp_cli --task vad` 退出码 1，stderr 末尾 `audiocpp_cli failed: failed to read WAV data chunk`；Metal 初始化日志在报错前正常打印（说明不是 GPU 问题）。
- 根因：缓存 `.../steno-merged-1080p_audio.wav` 是**上一次被取消的提取**留下的半成品。日志 17:05:36 起任务、17:05:38 取消，ffmpeg 子进程 `kill_on_drop` 被中途杀掉，WAV 头未回填 → `RIFF size` 与 `data size` 均为 `0xFFFFFFFF`，body 截断在 3,670,016B（≈114.7s，只占应到的 ~23.9MB 的 15%），文件正好停在 4096 页边界。
- 为何反复失败：`is_cache_fresh()`（transcribe.rs:1742）只比较 mtime；半成品 mtime=17:05:38 新材料，> 源文件 Nov 12 → 被判“新鲜”复用，于是每次重试都拿坏 WAV 喂 VAD，必失败。`remove_partial_outputs()`（:2180）只删字幕输出，不清 `*_audio.wav` 缓存。
- 复现：用 bundled audiocpp_cli 对坏 WAV 跑同样的 vad argv → 完全一致的报错、exit 1；同一视频重跑 ffmpeg（相同滤波链常量 AUDIO_FILTER_CHAIN）→ 23,914,574B、RIFF/data size 正确、VAD exit 0 / 159 chunks。证明源与 ffmpeg 正常，问题只在缓存。
- 处置：已验证并删除坏缓存 `steno-merged-1080p_audio.wav`，下次运行会重新提取（带进度）。
- 建议代码加固（未改）：①`is_cache_fresh` 增加完整性校验（riff_size≠0xFFFFFFFF 且 data_size==文件剩余长度，或直接试读 WAV）；②`run_ffmpeg` 写 `cache.part` 成功后原子 rename，失败/取消不留半成品；③取消清理时一并删除本次写入的 audio 缓存。
